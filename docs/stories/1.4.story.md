# Story 1.4: Display Generated Schedule

## Status
Completed

## Story

**As a** coach,
**I want** to see the generated schedule in a clear, readable format,
**so that** I can use it during the tournament.

## Acceptance Criteria

1. "Generate Schedule" button triggers algorithm and displays results
2. Schedule displayed as HTML table with columns: Round, Team, Driver 1, Driver 2, Loader
3. Table uses Tailwind CSS styling for readability (borders, padding, alternating row colors)
4. Each cell shows student name clearly
5. Table is responsive and readable on desktop/tablet screens
6. Empty state message shown before generation: "Enter student names and click Generate"
7. If inputs are invalid (empty names, 0 rounds), display error message instead of generating
8. Table suitable for projection (readable from distance) and printing (clear text, good contrast)

### Data Models

**Round Object Structure:**
```javascript
{
  roundNumber: number,   // Round identifier (1-indexed)
  teams: Team[]          // Array of team compositions
```

**Team Object Structure:**
```javascript
{
  teamNumber: number,    // Team identifier (1 or 2)
  driver1: string,       // First driver's name
  driver2: string,       // Second driver's name
  loader: string         // Loader's name
}
```

**ScheduleData State (Alpine.js x-data):**
```javascript
{
  studentNames: string,  // Textarea input (bound with x-model)
  numRounds: number,     // Number input (bound with x-model)
  numTeams: number,      // Number input (bound with x-model)
  students: Student[],   // Parsed student objects (generated by parseStudents())
  rounds: Round[],       // Generated schedule (populated by runGreedyFillAlgorithm())
  errorMessage: string,  // Validation errors (set by validateInputs())
  isGenerated: boolean   // UI state flag (false initially, true after generation)
}
```

### Component Specifications

[Source: docs/architecture/components.md]

**Schedule Display Component Responsibilities:**
- Render generated schedule as HTML table
- Use Alpine.js `x-show` directive to toggle visibility based on `isGenerated` flag
- Use Alpine.js `x-for` loops to iterate over `rounds[]` and nested `teams[]` arrays
- Consume `rounds[]` data populated by Algorithm Engine

**Action Buttons Component:**
- `@click` handlers for `generateSchedule()` method
- `x-show` conditional rendering based on `isGenerated` flag
- Trigger Algorithm Engine methods and display results

**Error Display Component:**
- `x-show` directive keyed to `errorMessage` presence
- `x-text` binding to display validation errors
- Red alert styling with Tailwind CSS

**Expected HTML Structure:**
```html
<div x-data="scheduleApp()">
  <!-- Header Section -->
  <h1>VexIQ Team Pairing Tool</h1>

  <!-- Input Form Section (already exists from Story 1.1) -->
  <textarea x-model="studentNames"></textarea>
  <input type="number" x-model="numRounds">
  <input type="number" x-model="numTeams">

  <!-- Action Buttons Section (NEW for Story 1.4) -->
  <button @click="generateSchedule()" x-show="!isGenerated">Generate Schedule</button>

  <!-- Error Display Section (NEW for Story 1.4) -->
  <div x-show="errorMessage" x-text="errorMessage"></div>

  <!-- Empty State (NEW for Story 1.4) -->
  <div x-show="!isGenerated">Enter student names and click Generate</div>

  <!-- Schedule Display Section (NEW for Story 1.4) -->
  <table x-show="isGenerated">
    <thead>
      <tr>
        <th>Round</th>
        <th>Team</th>
        <th>Driver 1</th>
        <th>Driver 2</th>
        <th>Loader</th>
      </tr>
    </thead>
    <tbody>
      <template x-for="round in rounds">
        <template x-for="team in round.teams">
          <tr>
            <td x-text="round.roundNumber"></td>
            <td x-text="team.teamNumber"></td>
            <td x-text="team.driver1"></td>
            <td x-text="team.driver2"></td>
            <td x-text="team.loader"></td>
          </tr>
        </template>
      </template>
    </tbody>
  </table>
</div>
```

### Coding Standards

[Source: docs/architecture/coding-standards.md]

**CRITICAL RULES for this story:**
- Use Alpine.js directives (`x-show`, `x-for`, `x-text`, `@click`) - NEVER use vanilla DOM APIs
- Validate before generation: Always call `validateInputs()` in `generateSchedule()` method
- Display errors via `errorMessage` property bound to `x-text`
- Use Tailwind CSS utilities for all styling - no custom CSS
- Print optimization required: Use `print:*` Tailwind classes for projection/printing
- Maintain single-file architecture: All HTML table code stays in index.html

**Naming Conventions:**
- Method name: `generateSchedule()` (camelCase)
- Data properties: `rounds`, `isGenerated`, `errorMessage` (camelCase)
- HTML IDs: `schedule-table` (kebab-case) if needed
- CSS classes: Tailwind utilities only (`border`, `p-4`, `bg-blue-600`)

**Alpine.js Directive Usage:**
- `x-show="isGenerated"` - Toggle table visibility
- `x-for="round in rounds"` - Iterate over rounds array
- `x-for="team in round.teams"` - Nested iteration for teams
- `x-text="round.roundNumber"` - Display round number
- `@click="generateSchedule()"` - Button click handler

### Tailwind CSS Styling Guidelines

[Source: docs/architecture/frontend-architecture.md, docs/prd.md#UI Design Goals]

**Table Styling Requirements:**
- **Borders:** `border border-collapse` for clean table structure
- **Padding:** `p-3` or `p-4` for comfortable cell spacing
- **Alternating rows:** `even:bg-gray-100` or `odd:bg-gray-50` for visual separation
- **Header styling:** `bg-blue-600 text-white font-bold` for distinct header row
- **Font sizes:** `text-base` (default) or `text-lg` for readability
- **Responsive:** `w-full overflow-x-auto` for table container (handles small screens)
- **Print utilities:** `print:text-lg print:border-black` for projection/printing
- **Contrast:** Dark text on light backgrounds (e.g., `text-gray-900` on `bg-white`)

**Button Styling:**
- Primary button: `bg-blue-600 hover:bg-blue-700 text-white font-bold py-2 px-4 rounded`
- Disabled state (if needed): `disabled:opacity-50 disabled:cursor-not-allowed`

**Error Message Styling:**
- Background: `bg-red-100` or `bg-red-500` (choose based on text color)
- Text: `text-red-700` (dark red on light background) or `text-white` (white on dark background)
- Padding: `p-4 mb-4` (comfortable padding and margin)
- Border: `border border-red-400 rounded` for clean alert appearance

**Empty State Styling:**
- Text color: `text-gray-500` (subtle but readable)
- Alignment: `text-center` for centered message
- Padding: `p-8` or `py-12` for vertical spacing

### Projection and Print Optimization

[Source: docs/prd.md#Non-Functional Requirements NFR7]

**Print-Friendly Requirements:**
- Table must be readable when projected from distance
- Table must print cleanly on 8.5×11 paper
- No critical information should be lost in grayscale printing

**Tailwind Print Utilities to Use:**
- `print:text-lg` - Increase font size for printing
- `print:border-black` - Ensure borders visible in print
- `print:text-black` - Force black text in print mode
- `@media print` CSS rules (if Tailwind utilities insufficient)

**Design Goals:**
- High contrast: Dark text on light backgrounds always
- Clear visual hierarchy: Header row stands out with distinct background
- Adequate spacing: Padding ensures text doesn't feel cramped when printed
