# Story 1.3: Variance Enforcement and Fairness Validation

## Status
Ready for Review

## Story

**As a** coach,
**I want** the algorithm to ensure no student gets significantly more opportunities than others,
**so that** all students perceive the schedule as fair.

## Acceptance Criteria

1. Algorithm tracks opportunity variance per role (driver variance, loader variance)
2. After each assignment, algorithm verifies variance ≤ 1 for both roles
3. If variance would exceed 1, algorithm backtracks or selects alternative student
4. Final schedule guarantees: max(driver_opportunities) - min(driver_opportunities) ≤ 1
5. Final schedule guarantees: max(loader_opportunities) - min(loader_opportunities) ≤ 1
6. Algorithm logs warnings (console) if perfect balance is mathematically impossible
7. Tested with edge cases: 5 students × 20 rounds, 25 students × 5 rounds, 8 students × 10 rounds

### Algorithm Specifications

[Source: docs/architecture/components.md#Algorithm Engine]

**Variance Enforcement Strategy:**

The greedy fill algorithm from Story 1.2 must be enhanced to check variance constraints before assigning students to roles. The variance for a role is defined as:

```
variance = max(roleCount) - min(roleCount)
```

Where `roleCount` is either `driverCount` or `loaderCount` for all students.

**Enforcement Approach:**
1. Before assigning a student to a role, check if assignment would cause variance > 1
2. Filter candidate students to only those that keep variance ≤ 1
3. If no candidates remain, log warning and use best-effort (assign anyway)
4. After full schedule generation, validate final variance for both roles

**Variance Calculation Pseudocode:**
```javascript
calculateVariance(role):
  countKey = (role === 'driver') ? 'driverCount' : 'loaderCount'
  counts = students.map(s => s[countKey])
  maxCount = Math.max(...counts)
  minCount = Math.min(...counts)
  return maxCount - minCount

wouldViolateVariance(student, role):
  // Simulate assigning student to role
  simulatedCount = student[countKey] + 1

  // Find max count across all students after simulation
  maxCount = Math.max(...students.map(s => s[countKey]))
  maxCount = Math.max(maxCount, simulatedCount)

  // Find min count across all students (unchanged by simulation)
  minCount = Math.min(...students.map(s => s[countKey]))

  // Check if simulated variance would exceed 1
  simulatedVariance = maxCount - minCount
  return simulatedVariance > 1
```

**Modified `selectStudentForRole()` Integration:**
```javascript
selectStudentForRole(role, assignedThisRound):
  available = students.filter(s => !assignedThisRound.has(s.id))

  if (available.length === 0):
    console.warn('No available students - reusing students in same round')
    return students[0]

  countKey = (role === 'driver') ? 'driverCount' : 'loaderCount'
  minCount = Math.min(...available.map(s => s[countKey]))
  candidates = available.filter(s => s[countKey] === minCount)

  // NEW: Filter candidates to those that don't violate variance
  varianceCompliant = candidates.filter(s => !this.wouldViolateVariance(s, role))

  if (varianceCompliant.length === 0):
    console.warn(`Perfect balance impossible for ${role} - using best-effort selection`)
    // Fall back to original candidates if variance cannot be maintained
    varianceCompliant = candidates

  return varianceCompliant[Math.floor(Math.random() * varianceCompliant.length)]
```

[Source: docs/architecture/core-workflows.md#Edge Case - Impossible Perfect Balance]

**Mathematical Impossibility Scenarios:**

Some tournament configurations make perfect variance ≤ 1 impossible:

- **Too few students, too many rounds:** Example: 4 students, 100 rounds, 2 teams requires 600 role assignments (100 × 2 × 3), but only 4 students available. Some students will get 150+ opportunities while others get fewer.
- **Odd total slots:** If total driver slots is not evenly divisible by number of students, variance of 1 is the best achievable.

When these scenarios occur:
1. Algorithm continues with best-effort assignment
2. Console warnings logged: "Perfect balance impossible for [role] - using best-effort selection"
3. Final validation logs actual variance: "Final variance exceeds target: driver=[X], loader=[Y]"

### Performance Considerations

[Source: docs/architecture/components.md]

Variance checking adds computational overhead to `selectStudentForRole()`:
- Original complexity: O(n) to find min count and select candidate
- With variance checking: O(n) + O(n) = O(2n) still O(n) per selection
- Total algorithm remains O(n×r×t) where n=students, r=rounds, t=teams
- For 30 students × 15 rounds × 2 teams: Still well under 1 second

**Optimization notes:**
- Cache variance calculations per round if performance issues arise (unlikely for MVP scale)
- Use Array methods (`map`, `filter`) efficiently - avoid nested loops
