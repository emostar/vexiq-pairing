## Dev Notes

All technical details extracted from architecture documentation to provide complete implementation context.

### Tech Stack

[Source: architecture/tech-stack.md]
- **HTML5** with ES2020 JavaScript
- **Tailwind CSS 3.x** via CDN (https://cdn.tailwindcss.com) - no build step required
- **Alpine.js 3.x** via CDN (https://cdn.jsdelivr.net/npm/alpinejs@3.x.x/dist/cdn.min.js) for reactive UI
- No build tools, bundlers, or npm dependencies
- Must work offline after initial CDN load (browser HTTP cache handles this automatically)

### Project Structure

[Source: architecture/unified-project-structure.md]
- **Single file architecture:** `index.html` contains ALL HTML, CSS, and JavaScript
- No separate .js or .css files allowed
- Flat structure - no src/, dist/, or components/ directories
- **File location:** Project root `./index.html`

### HTML Structure Required

[Source: architecture/frontend-architecture.md]

The complete structure needed:

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>VexIQ Team Pairing Tool</title>
  <script src="https://cdn.tailwindcss.com"></script>
  <script defer src="https://cdn.jsdelivr.net/npm/alpinejs@3.x.x/dist/cdn.min.js"></script>
</head>
<body>
  <div x-data="scheduleApp()">
    <!-- Header section -->
    <!-- Input form section -->
    <!-- Action buttons section (future story) -->
    <!-- Error display section (future story) -->
    <!-- Schedule display section (future story) -->
  </div>
  <script>
    function scheduleApp() {
      return {
        // Data properties
        studentNames: '',
        numRounds: 5,
        numTeams: 2,
        // Methods will be added in future stories
      };
    }
  </script>
</body>
</html>
```

### Alpine.js Component Structure

[Source: architecture/frontend-architecture.md, architecture/components.md]
- **Main component:** `scheduleApp()` function returns reactive object
- Use `x-data="scheduleApp()"` directive on main container div
- Use `x-model` for two-way data binding on form inputs
- All application state lives in the reactive data object returned by scheduleApp()
- Script tag with scheduleApp() function must be placed at end of body (before closing </body> tag)

### Input Form Specifications

[Source: architecture/components.md#Input Form]

**Textarea (Student Names):**
- Bound to `studentNames` property via `x-model="studentNames"`
- Placeholder text: "Enter student names, one per line"
- HTML element: `<textarea>`
- Use Tailwind classes for styling

**Number Input (Rounds):**
- Bound to `numRounds` property via `x-model.number="numRounds"`
- Label text: "Number of Rounds"
- HTML attributes: `type="number" min="1" max="99"`
- Default value: 5
- Use Tailwind classes for styling

**Number Input (Teams):**
- Bound to `numTeams` property via `x-model.number="numTeams"`
- Label text: "Number of Teams"
- HTML attributes: `type="number" min="1" max="2"`
- Default value: 2
- Use Tailwind classes for styling

### Data Model

[Source: architecture/data-models.md#ScheduleData]

Initial data properties required for this story (returned from scheduleApp() function):

```javascript
{
  studentNames: '',      // string - bound to textarea
  numRounds: 5,          // number - bound to rounds input
  numTeams: 2            // number - bound to teams input
}
```

Other properties (students, rounds, errorMessage, isGenerated) will be added in future stories.

### Coding Standards

[Source: architecture/coding-standards.md]

**CRITICAL RULES:**
- All code MUST remain in single `index.html` file - never create separate .js or .css files
- Use Alpine.js directives for DOM manipulation (`x-data`, `x-model`) - never use vanilla DOM APIs like `querySelector`, `innerHTML`, or `addEventListener`
- Use Tailwind utility classes for ALL styling - no custom CSS
- No external dependencies beyond Tailwind + Alpine.js CDNs
- No localStorage, sessionStorage, or persistence mechanisms in this story

**Naming Conventions:**
- JavaScript functions and variables: camelCase (`scheduleApp`, `studentNames`, `numRounds`)
- HTML IDs (if needed): kebab-case (`student-input`, `rounds-input`)
- Tailwind classes: use standard Tailwind utilities (`bg-blue-500`, `p-4`, `text-center`)

### Styling Guidelines

[Source: architecture/coding-standards.md, docs/prd.md#UI Design Goals]
- Use Tailwind utility classes exclusively for styling
- Create responsive layout that works on desktop (primary) and tablet viewports
- Professional, clean appearance following "radical simplicity" design principle
- Not a consumer app - should feel like a professional coaching tool
- Ensure good visual hierarchy (heading clear and prominent, inputs organized logically)
- Use appropriate spacing (Tailwind padding/margin utilities) for readability

### Layout Guidance

[Source: docs/prd.md#User Interface Design Goals]
- **Single-screen interface:** All elements on one page, no navigation
- **Visual hierarchy:** Input section at top, results will appear below in future stories
- **Logical flow:** Heading → Inputs → (future: Action buttons → Results)
- **Paste-friendly:** Textarea should be large enough for comfortable pasting of student lists

### Testing

[Source: architecture/tech-stack.md]

Testing approach for MVP is **manual testing only** (no automated test framework due to 4-5 hour timeline constraint).

**Manual Testing Checklist:**

1. **File Structure Validation:**
   - Verify `index.html` exists in project root
   - Verify it contains valid HTML5 structure

2. **CDN Loading:**
   - Open `index.html` directly in browser using `file://` protocol
   - Open browser DevTools Network tab
   - Verify Tailwind CSS loads successfully from cdn.tailwindcss.com
   - Verify Alpine.js loads successfully from cdn.jsdelivr.net
   - Check Console tab for any load errors

3. **Alpine.js Initialization:**
   - Open browser DevTools Console
   - Verify no Alpine.js errors appear
   - Type `Alpine.version` in console to confirm Alpine loaded
   - Verify `x-data` directive successfully mounts

4. **UI Elements Present:**
   - Verify page heading "VexIQ Team Pairing Tool" displays
   - Verify textarea appears with placeholder "Enter student names, one per line"
   - Verify "Number of Rounds" label and input appear
   - Verify "Number of Teams" label and input appear

5. **Form Functionality:**
   - Type text into textarea
   - Change value in rounds input (verify min=1, max=99 constraints)
   - Change value in teams input (verify min=1, max=2 constraints)
   - Use browser DevTools console to inspect Alpine data: Check `$data` to verify x-model bindings update state

6. **Responsive Layout:**
   - Resize browser window to desktop width (1920px)
   - Verify layout looks organized and readable
   - Resize to tablet width (768px)
   - Verify layout remains functional and readable

7. **Cross-Browser Compatibility:**
   - Test in Chrome (latest version)
   - Test in Firefox (latest version)
   - Test in Safari (latest version, if available)

**No Test Files Required:**
No test files, test framework, or test configuration needed for this story. All validation is manual browser testing.
